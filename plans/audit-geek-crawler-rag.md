# Geek-Crawler-Rag — Code Audit

**Date:** 2026-10-09

## Scope and method

This is the most rule-sensitive repo in the system — the one place a "never generates" violation would matter most — so it got the deepest, most targeted verification rather than a uniform line-by-line pass across all 42 source modules (13,414 lines in `src/geek_crawler_rag/`). Specifically:

- **Every route in `src/geek_crawler_rag/app.py` was enumerated and inspected** (35 endpoints), confirming there is no `/v1/generate` route and no route that composes original prose.
- **File names that read as alarming given the "never generates" rule were investigated to the implementation, not just the model layer**: `intelligence.py` (1,222 lines), `intelligence_models.py`, `ad_templates.py`, `diagnostics.py`, `agent_models.py`. Golden fixture names like `pillarOutline`, `faqSet`, `comparisonBrief` and `competitiveResponse` were traced to confirm whether they represent live generation.
- **A whole-repo grep for any LLM provider call** (`openai`, `anthropic`, `chat.completions`, `.complete(`) across every `.py` file, and a check of `pyproject.toml`'s dependencies for an LLM client library.
- **A whole-repo grep for `markdown`, `generate`, `retry`/`retries`/`backoff`, `RagLibraryStatus`, `generateEnabled`** to independently verify the claims this project's own CLAUDE.md makes about this repo's migration status, rather than trusting them.
- **`.cursor/rules/no-retries-no-fallbacks.mdc` was read in full** (this repo's version differs materially from the crawler's — it documents a specific retry regression and reversal, dated 2026-09-28) and checked against current code.
- Dead-code tracing: any module suspected of being unreachable from `app.py` was grep-checked against every other source file, script and test file in the repo, not just against `app.py` imports.
- Core pipeline files read in full: `block_text.py`, `citation_verify.py`, `extract.py`, `ad_templates.py`, `embedding_circuit.py`, `status_store.py` (the lease/retry-scheduling logic), relevant sections of `indexer.py`, `llama_engine.py`, and `app.py`'s auth/health/error-handling scaffolding.
- Test coverage confirmed by listing: 66 test files for 42 source modules.

The remainder of these larger files was grep-verified against the same rule set, not read end to end — a further pass of those specific files is the natural next step for a deeper audit of this repo.

## What this service is

A Python/FastAPI service (`src/geek_crawler_rag/app.py`, 35 routes) that is the "Library half" of RAG: it ingests the crawler's typed-block corpus from Mongo, chunks and embeds it locally (no external embedding API — `BAAI/bge-small-en-v1.5` via `fastembed`, run off the event loop in a worker thread), indexes it into Qdrant with hybrid dense+BM25-sparse vectors, and serves retrieval (`/v1/query`), quote verification (`/v1/verify`), and page-text lookup (`/v1/pages`). It never generates prose.

- **Ingest/index**: `indexer.py` claims a content-ready run (Mongo lease-based scheduling, `status_store.py`), builds parent/child chunks from typed blocks (`chunk.py`, `llama_nodes.py`), embeds locally (`local_embedding.py`), and upserts to Qdrant (`qdrant_store.py`). An embed failure quarantines the batch to disk and fails the run closed (`embedding_circuit.py`) — never silently continues with a gap.
- **Single plaintext projection**: `block_text.py`'s `derive_plaintext_from_blocks` is the one function that turns typed blocks into a string, consumed identically by the chunker (`chunk.py`) and by citation verification (`citation_verify.py`) — exactly the design CLAUDE.md credits this repo for, and confirmed by direct read, not just by trusting the claim.
- **Verification**: `POST /v1/verify` (`citation_verify.quote_in_text`/`verify_quote`) checks a quote against the same block projection GeekAPI's C# side derives from the same blocks, with two specific, measured, deliberately-tolerated divergences (escaped markup, empty table cells) and nothing else normalized.
- **Deterministic "intelligence" analysis** (`intelligence.py`, `diagnostics.py`, `ad_templates.py`): competitor-page analysis, content-gap detection, AI-readiness scoring, and ad-template few-shot retrieval — all pattern-matching over caller-supplied page content, with zero LLM calls anywhere in the repo (confirmed: no `openai`/`anthropic` import, no LLM client in `pyproject.toml`'s dependencies). Where a "hypothesis" or suggested message is produced, it is built from a fixed f-string template and is explicitly typed and disclaimed (`MessagingHypothesis.origin: Literal["generatedHypothesis"]`) rather than presented as fact or as model output.
- **Scheduling**: a durable background scheduler (`scheduler.py`, `status_store.py`) indexes the oldest content-ready run with no job row, because GeekAPI's own trigger call fails closed and only logs on a miss — this scheduler is the only automatic catch-up for a run GeekAPI failed to notify about.
- **Push, not pull**: index status reaches GeekAPI over a webhook (`webhook.py`) to a SignalR bridge; there is no polling anywhere in the repo.

## Critical and high findings

**None at critical severity for the rule most likely to be violated here.** The "RAG never generates" boundary was investigated hardest, precisely because file names like `intelligence.py` and `ad_templates.py`, and golden fixtures like `pillarOutline`, `faqSet`, `comparisonBrief` and `competitiveResponse`, read as alarming on their face. Investigation to the implementation — every route enumerated, zero LLM-provider imports anywhere in the repo, zero LLM client in `pyproject.toml`, the hypothesis-construction code read in full and confirmed to be fixed f-string templates — found no generation. This is worth stating plainly rather than just clearing: the repo is compliant, and more carefully guarded against drifting into generation (explicit `Literal["generatedHypothesis"]` typing, disclaimer strings baked into every artifact) than the rule strictly requires.

**High — a third, independently-drifted copy of the locale-exclusion rule, this one deciding live corpus eligibility, carrying the same bug the crawler already fixed.** `src/geek_crawler_rag/unusable.py`'s `should_exclude_locale_path` (used by `classify_unusable_page`, which the indexer calls to decide whether an already-crawled page may be indexed) implements its own copy of the locale filter, with its own copy of `DROP_REGION`/`NON_ENGLISH_LOCALE` sets and its own `_primary_lang`. That helper is `seg.lower().split("-", 1)[0]` — the exact pre-fix logic Geek-Crawler-v2's own `locale-path.ts` replaced on 2026-09-30 after measuring that it let 264 GB-market pages into a US crawl under compound tags like `en-gb`. `unusable.py`'s module comment claims it "mirrors Geek-Crawler-v2 locale-path rules," but it mirrors the version from before that fix: a page whose path starts `/en-gb/...` passes `_primary_lang("en-gb") == "en"` and is kept as if it were a US/English page, rather than excluded.

*Why this is higher severity than the content-creator-v2 and web-UI copies of the same bug found elsewhere in this audit*: those were display-only estimates. This one decides whether a real, already-crawled page is eligible to be chunked, embedded and returned as a retrieval or citation source — it is a live correctness defect in what the Library actually serves, not a cosmetic one. **Recommendation**: delete `unusable.py`'s private locale constants and `_primary_lang`, and have it call the crawler's fixed, BCP-47-aware `parseLocaleSegment` logic (or a Python port of it) instead — the same fix content-creator-v2's `locale-path.ts` copy needs, now needed in a third place.

## Medium and low findings

**Low — `agent_models.py` and `skills.py` (793 lines combined) are transitively dead code.** Neither is imported by `app.py` or any other production module, script, or test — confirmed by grepping every `.py` file in `src/`, `scripts/`, and `tests/` for any reference to `geek_crawler_rag.skills`. `skills.py` implements HMAC-signed skill-execution-snapshot verification (digest, signature, canonical payload) for an "immutable reviewed skills" concept that `agent_models.py` types (`AgentTrace`, `SignedSkillExecutionEnvelopeV2`, stop reasons, retry-of-stage-execution tracking). Whatever system this was built to support, it is not wired into this service's live HTTP surface today.

**Low — a second, unused HTML-to-text extraction path exists alongside the canonical blocks projection.** `extract.py` defines both `page_text_and_title` (the live path, built on the single `derive_plaintext_from_blocks` projection) and `extract_text_and_title` (a BeautifulSoup HTML-to-text function). Grep confirms `extract_text_and_title` is called only by its own test (`tests/test_extract.py`) — no production code path reaches it. It is not currently a corpus-format violation (nothing routes real pages through it), but its mere presence is exactly the risk this project's own rules warn about: a second "derive text from this page" implementation sitting in the same module as the canonical one, one accidental wire-up away from reintroducing the drift that caused 5,274 pages to be deleted once before.

**Not a finding, worth recording as a positive**: the `index_scheduler_max_attempts`/`index_scheduler_retry_seconds` settings in `config.py` look, from the names alone, like they could be an automatic failure-retry loop — forbidden by this repo's own `no-retries-no-fallbacks.mdc`. Reading `status_store.py` confirms they are not: `attempt` counts explicit re-claims of a job (an operator or scheduler re-enqueueing a run still eligible to run), capped as a circuit breaker (`excluded_run_ids`) rather than a background auto-retry, and `release()` explicitly sets `nextRetryAtUtc = None` for any job in the `FAILED` state with the comment "operator must inspect quarantine / re-enqueue manually." This distinction is drawn carefully and correctly in the code; it would have been an easy one to get wrong.

## Cross-service contracts

- **`POST /v1/index` is triggered by GeekAPI on run completion and fails closed with only a log line when this Library is unreachable** (per `config.py`'s own comment: "on 2026-09-24 eleven crawls completed unindexed that way"). The scheduler here is the sole automatic catch-up. Worth confirming on the GeekAPI side that this trigger's failure is at least surfaced to an operator somewhere, not just logged.
- **`POST /v1/verify` and GeekAPI's `GccCorpusBlockMapper` project the same blocks independently** (Python here, C# there) and are known, measured and deliberately tolerated to diverge in exactly two ways (escaped markup, empty table cells) — `citation_verify.py`'s own comment names a shared fixture (`contracts/block-projection/v1.json`) pinned by tests on both sides as the contract that keeps them in sync. This is a good pattern: the two-implementation drift risk the project is otherwise very alert to is here, but it is measured, bounded, tested on both sides, and explicitly normalized rather than silently tolerated.
- **`ad_templates.py` retrieves operator-authored templates reached through a GeekRepository route** (`repo/content-creator-v2/ad-templates`, per this file's own comment citing `HttpGccV2Repository.cs:302-304`) — worth checking against the GeekRepository report for whether that route still exists and matches.
- **Index status webhook contract** (`contracts/rag-index-status/webhook.v1.json`) is versioned and has its own contract test (`test_index_status_webhook_contract.py`, `scripts/compare_webhook_contract.py`) — a good example of exactly the kind of cross-repo contract test this audit recommends elsewhere where one does not yet exist (e.g., the crawler/GeekAPI batch-size mirror).

## Tests and verification

**Strong coverage by file count**: 66 test files for 42 source modules, including contract tests (`test_block_projection_contract.py`, `test_index_status_webhook_contract.py`, `test_compare_webhook_contract.py`), golden-fixture tests for every intelligence/diagnostic artifact type, and specific regression tests for defects this audit independently rediscovered evidence of in other repos — `test_sitemap_exclusion.py`, `test_mongo_value_shapes.py` (guards against exactly the string-vs-bool/int encoding mismatch `unusable.py`'s own comment calls out), `test_chunk_fits_the_model.py` and `test_chunk_hit_structure_fields.py` (guard the WordPiece/tiktoken drift that silently truncated 6.9% of parents).

**Gap found by this audit**: no test exercises `unusable.py`'s locale exclusion against a compound tag like `en-gb` — which is exactly how the crawler's own version of this bug went unnoticed until it was measured in production. A test asserting `should_exclude_locale_path("https://site.com/en-gb/pricing")` is `True` would have caught the High finding above immediately, and is the single highest-value test to add from this audit.

**Not independently verified**: whether the 160+ assertions in the larger untouched-by-this-pass files (`indexer.py`, `qdrant_store.py`, `mongo.py`, `llama_engine.py`, `status_store.py`) actually exercise their full branch coverage, versus asserting only the happy path — that would require reading those test files against their source files line by line, which this pass did not do.

## Recommended fix order

1. Fix `unusable.py`'s locale exclusion to use the fixed, BCP-47-aware logic (High — this is a live corpus-eligibility defect, the single most important fix in this repo).
2. Add the regression test that would have caught it: `should_exclude_locale_path` against a compound tag like `en-gb`, `en-au`, etc.
3. Decide whether `agent_models.py`/`skills.py` are a future integration point worth keeping dormant, or dead weight worth deleting — either answer is fine, but 793 unwired lines implementing HMAC-signed execution verification is worth a deliberate decision rather than silent accumulation.
4. Delete `extract.py`'s unused `extract_text_and_title`, or at minimum move it out of the module that holds the canonical projection, so the one-true-projection property is visible from the file list, not just from which function happens to get called.
5. No other action needed on the rule this repo exists to protect: the Library-only boundary is intact, carefully typed, and more defensively guarded than the letter of the rule requires.
